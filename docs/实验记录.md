## 实验结论

### 物理布局不是原因（#2 vs #4）

把 `0x0/0x200000` 改成 `0x80000000/0xA8000000` 后，所有内核地址平移 638 MB：

```
init_cred alias:  0xffffff80022f0548  →  0xffffff802a0f0548
W1 target:        0xffffff8002515f68  →  0xffffff802a315f68
```

**崩溃点完全不变** ⇒ 物理布局与能否成功无关。
后续从官方 ROM（vendor_boot header + DTB）证实 `kernel_addr=0x200000`、`RAM base=0`，
即原值本来就是对的。

### shift 的合法范围只有三个值

fd_set 共 15 字（下标 0–14），waiter 占第 2–14 字，故约束：

```
2 + shift ≥ 0  且  14 + shift ≤ 14   ⇒   shift ∈ {−2, −1, 0}
```

`shift=1` 越界（实测 #5 直接报错，未进入内核）。三个合法值实测：

| shift | 表现 |
|---|---|
| −2（+text_addr） | soft lockup，链走进垃圾后死循环 |
| −1 | panic |
| 0 | panic，`waiter->lock` 读出 0 |

### 两个 bug 必须同时修（#7 vs #8 是关键对照）

| | shift | 指针 | 结果 |
|---|---|---|---|
| #7 | 0（错） | data_addr（对） | ❌ 仍 NULL deref |
| #8 | −2（对） | data_addr（对） | ✅ 成功 |

**#7 证明**：只修 KASLR 不够，栈对齐错时 `lock` 字段仍落在零填充区。
