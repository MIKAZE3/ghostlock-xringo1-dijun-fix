# dijun 内核静态分析报告

> 目标：确定 CVE-2026-43499 (GhostLock) 在原版 APK 上失败的原因。
> 数据来源：设备内 `/storage/emulated/0/boot.img`（96 MB，Android boot header v4）
> 方式：纯静态分析 + 只读探测，未在分析阶段运行任何 exploit。

## 1. 镜像结构

| 项目 | 值 |
|---|---|
| boot.img 大小 | 100,663,296 字节 |
| Boot header | `ANDROID!`，v4，header_size=0x630 |
| 内核本体 | boot.img 偏移 `0x1000`，**未压缩** |
| 格式 | PE32+ / COFF arm64（EFI，`MZ` 头），ImageBase=0 |
| `.text` | VMA/文件偏移 `0x10000`，RawSize `0x02060000` |

**文件偏移 == 虚拟地址**，因此「镜像偏移」可直接当文件偏移使用。

## 4. kallsyms 解析

原版镜像 kallsyms 名称经过压缩，直接扫描 `token_table + token_index` 签名会失败。
关键坑：**`token_table` 与 `token_index` 之间有 2 字节对齐填充**，
且 `0x115D4E0` 处存在 `u16=[0,1,2,...,255]` 的假表干扰。

正确判据是把「递增」升级为**前缀和恒等**：`token_index[i]` 必须精确等于第 i 个字符串在表中的偏移。

| 数组 | 偏移 | 规模 |
|---|---|---|
| `kallsyms_num_syms` | 0x0131E6D8 | 4 B = 108902 |
| `kallsyms_names` | 0x0131E6E0 | 1,519,660 B |
| `kallsyms_markers` | 0x01491710 | 426 × u32 |
| `kallsyms_token_table` | 0x01491DB8 | 910 B |
| `kallsyms_token_index` | 0x01492148 | 256 × u16 |
| `kallsyms_offsets` | 0x01492348 | 108902 × s32 |
| `kallsyms_relative_base` | 0x014FC8E0 | `0xFFFFFFC080000000` |

本镜像**无** `kallsyms_seqs_of_names`（6.1 式布局）。

### 交叉验证（4 重）

1. **锚点**：`init_task=0x020DE280`（+0x830 = `swapper`）、`init_cred=0x020F0548`，误差 0
2. **字符串**：`linux_banner=0x0131E590`，该处正是 `Linux version 6.6.77-android15-…`
3. **反汇编**：`start_kernel=0x01CB041C` 首指令 `paciasp`，函数体 `adrp/add` 引用
   `0x020DE280`(init_task) 与 `0x0131E590`(linux_banner)
4. **指针表**：`sys_call_table=0x01080CB8` 前 460 项 **460/460** 命中，
   slot 172 = `__arm64_sys_getpid`、220 = `clone`、221 = `execve`

## 6. 栈帧计算（决定 waiter_shift）

| 函数 | `sub sp` | frame reference |
|---|---|---|
| `__arm64_sys_futex` | −0x70 | x29 = sp+0x20 |
| `do_futex` | −0x60 | x29 = sp+0x40 |
| `futex_wait_requeue_pi` | **−0x1c0** | waiter 在 **sp+0x90** |
| `__arm64_sys_pselect6` | −0x90 | x29 = sp+0x30 |
| `core_sys_select` | **−0x1f0** | stack_fds 在 **sp+0x80** |

调用方式确认（非尾调用）：
- `__arm64_sys_futex` @+0xa4 处 `bl 0x19fed4`(do_futex)
- `do_futex` @+0xd0 处 `bl 0x1a2890`(futex_wait_requeue_pi)
- `__arm64_sys_pselect6` @+0x120 处 `bl 0x3dfdf4`(core_sys_select)
- `invoke_syscall` @+0x54 处 `blr x8`（间接调用，两条链深度相同）

推导：

```
futex:   waiter_abs = S₀ − 0x70 − 0x60 − 0x1c0 + 0x90 = S₀ − 0x200
pselect: fds_abs    = S₀ − 0x90 − 0x1f0 + 0x80        = S₀ − 0x200
⇒ waiter − stack_fds = 0
⇒ 8 × (shift + 2) = 0 ⇒ shift = −2
```

对照实现：Linux 6.6 `kernel/select.c` 中
`stack_fds = SIZEOF_STATIC_SETS + sizeof(fd_set) * 3`、
`fds.in = (unsigned long *)(stack_fds + 0)`、`fds.out = stack_fds + n`（n = bits/8）、
`fds.ex = fds.out + n`。本镜像 `ADD(ADD(X20, X25), X25)` 结构完全对应。

## 7. KASLR 状态

| 证据 | 值 |
|---|---|
| `CONFIG_RANDOMIZE_BASE` | `y` |
| `/chosen/bootargs` | 无 `nokaslr` |
| panic #44（12:12:56） | `Kernel Offset: 0x24f8e00000` |
| panic #43（10:04:25） | `Kernel Offset: 0x2ce6000000` |

**两次不同 ⇒ KASLR 生效。** 理论范围（6.6 `kaslr_early.c`）：
`slide = 2^36 + (seed & (2^37−1))`，2 MiB 对齐 ⇒ `[0x1000000000, 0x3000000000)`。

> 尝试用 `perf_event_open` 直接采样内核 IP 失败：SELinux 拒绝
> `avc: denied { kernel } ... tclass=perf_event permissive=0`。
> 注意 `perf_event_paranoid = -1`（比默认宽松），拦截者是 SELinux 而非 paranoid。

## 8. 内存布局（vendor_boot + DTB）

`vendor_boot.img`（`VNDRBOOT` v4, page_size=4096）：

| 字段 | 值 |
|---|---|
| `kernel_addr` | **0x200000** |
| `ramdisk_addr` | 0x4400000 |
| `dtb_addr` | 0x4200000 |
| dtb_size | 180,602 |

DTB `/memory@0 reg` = `0x0 + 0xC0000000`、`0x100000000 + 0x100000000`、`0x800000000 + 0x40000000`
⇒ **RAM 基址 = 0**

`/chosen/bootargs` = `kasan=off rdinit=/init printk.devkmsg=on rcupdate.rcu_expedited=1 rcu_nocbs=0-9`
⇒ **`kasan=off`**：MTE 运行时关闭（虽编译进内核）。

**结论：`phys_offset=0`、`kernel_phys_load=0x200000` 是正确值。**
（曾误改为 `0x80000000/0xA8000000`——那是 KSuRoot 的通用 ABI 常量，不适用本机；
实验证明改后崩溃点完全不变。）

反汇编对照（`rt_mutex_adjust_prio_chain` = 0x01052868）：

```asm
105298c: f9402f38   ldr x24, [x25, #0x58]   ; x24 = waiter->lock  (x25 = task->pi_blocked_on)
1052990: aa1803e0   mov x0, x24
1052994: 9400068d   bl  0x10543c8           ; _raw_spin_trylock(lock)
1052998: 350004a0   cbnz w0, ...            ; ← LR = +0x130
```

`_raw_spin_trylock` = 0x010543c8：

```asm
10543e4: b9400009   ldr w9, [x0]            ; ← +0x1c，x0=0 时读地址 0
```

**`lock` 字段（waiter+0x58）读出 0** ⇒ 伪造 waiter 与内核栈错位，该位置是零填充区域。
